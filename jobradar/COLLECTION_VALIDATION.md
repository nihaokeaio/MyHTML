# 本地采集验证（2026-11-15）

环境：Windows，Python 3.10；urllib 默认 TLS 证书验证，明确标识 JobRadar User-Agent。未绕过验证码或访问控制。

## 调查结论

- 原代码已有逐来源异常隔离、URL 哈希去重和失败非零退出码；主要漏洞是 HTTP 200 空页/栏目导航也算成功，日志缺少结构字段。
- 人社厅首页与旧栏目 HEAD/GET 在本轮均返回 200，之前的 403 未稳定复现。旧栏目 1654 字节，JS 跳转到 `/col/col1229743683/index.html`。
- 新栏目首次 GET 403，后续返回 200、5192 字节，但未提取到静态公告详情，只有招聘栏目导航；故按失败报告，未尝试绕过限制或探测隐藏接口。
- 不能据此认定是 HEAD 方法导致 403。URL 和返回内容存在差异，网络出口、时段、服务端策略可能影响结果，具体策略无法确认。GitHub Actions 的 TLS 超时发生在 HTTP 之前，不能用本地 HTTP 结果证明已修复。
- 部分 cas.cn 官方站点本地出现证书校验失败；未关闭证书验证，未加入采集来源。

## 变更范围

保持 GitHub Pages 和既有 jobs 字段；新增 source_results。结构化 JSON 日志记录请求响应、失败分类及总计。非临时错误（4xx、证书、内容类型/大小异常）不重试；临时网络错误最多三次。空结果保守报错，便于发现栏目改版。通过临时文件替换写入数据。

Actions 保留采集失败状态，上传日志与数据 artifact；即使部分来源失败仍允许原有 main 数据更新步骤保存成功来源数据，测试失败则不触发数据提交。未推送或触发远端 Actions，因此 GitHub 网络可达性尚待后续运行验证。


## 第二轮：正文解析与初筛

新增 scripts/enrich_jobs.py，先运行 collect_jobs.py，再运行 enrich_jobs.py。两步独立退出，前一步失败不阻断已有候选的正文处理；任何正文失败均退出 1，同时原子保存成功结果。Actions 已接入正文分析及日志 artifact，未运行远端 Actions 或推送。

本地对 16 条公告实际 GET：正文成功 9 条（浙大 3、浙工商 6），失败 7 条（浙大 4、浙工商 3），全部失败项跳转到学校 CAS 登录页，未尝试认证。正文成功项有 2 条录用公示、7 条招聘公告；没有确认符合用户条件的岗位。

新增公告分类、学历/专业/经验/招聘对象/地点/用工/报名期限的原文片段及来源 URL、技术线索、附件链接。仅解析 wp_articlecontent 正文区域，排除导航及脚本。技术词命中不代表软件岗位，例如普通行政岗位要求熟练使用计算机，也会留下计算机线索。

期限仅接受报名语境下明确完整年月日，歧义日期保留未知。实际提取到 4 条明确日期，均早于本轮验证日期，网页标记已过期；没有明确期限的公告不标记仍可报名。学历提到博士不直接排除多岗位公告，应届身份和校内资格未确认时保留人工核实。现阶段不输出“明确符合”，岗位附件仅提供官方链接，尚未下载解析；证据字段是正文线索，不是逐岗位结构化结论。

网页增加人工核实、流程公告、正文失败筛选，展示筛选理由、条件证据及附件链接。保留原 jobs 数据字段、ID 去重与标题评分，新增字段兼容现有 GitHub Pages。失败时旧证据注明可能过时，不保留旧的肯定筛选结论。

验证：17 项单元测试通过，包含正文边界、多岗位学历、日期语义、附件相对链接、登录重定向、正文部分失败持久化；Node VM 对网页渲染、四种筛选及危险 URL 拒绝通过检查。未进行真实浏览器视觉检查。
